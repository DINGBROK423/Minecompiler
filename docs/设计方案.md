# C-- 编译器前端工程设计方案

## 1. 工程目标

本工程实现一个手写 C-- 编译器前端：

```text
.sy source
  -> Lexer: NFA / DFA / minimized DFA
  -> TokenStream + lexical symbol table
  -> Grammar Engine: FIRST / FOLLOW + LR(0) items + SLR table
  -> SLR Parser: move / reduction / accept / error trace
  -> AST
  -> Semantic Analyzer: scopes / types / functions / const
  -> IR Generator backend
  -> .ll
```

工程强调四点：可运行、可解释、可验证、可展示。

## 2. 模块划分

```text
include/, src/
  lexer      NFA, DFA, MinDFA, Lexer
  grammar    Production, FIRST/FOLLOW, LR(0), SLRTable
  parser     SLRParser, ParseTrace, AstBuilder
  ast        AstNode, text printer, DOT exporter
  semantic   Symbol table, Scope stack, Type checking
  ir         compiler_ir adapter + float fallback backend
  driver     CLI, diagnostics, artifact dumping
CMakeLists.txt
  CMake build entry, links compiler_ir as a static library
Makefile
  Make build/test/demo/ui entry
tests/
  lexer, valid, invalid, ir
scripts/
  run_tests.sh
ui/
  local web dashboard
```

## 3. 词法分析

词法器保留自动机构造全过程：

1. 为关键字、运算符、界符、标识符、整数、浮点数、空白构造 NFA 片段。
2. 用 epsilon 边合并为一个大 NFA。
3. 通过子集构造生成 DFA。
4. 通过等价类划分最小化 DFA。
5. 扫描时采用最长匹配策略。

增强点：

- 关键字大小写不敏感。
- `main` 按关键字输出。
- 支持 `//` 注释。
- 非法字符输出 `ERROR` 并记录诊断。
- 可导出 `*.dfa.csv`。
- 可输出标识符符号表。

## 4. SLR 语法分析

语法器不是手写表，而是程序自动构造：

1. 内置 BNF 文法。
2. 增广文法 `S' -> Program`。
3. 计算 FIRST / FOLLOW。
4. 构造 LR(0) 项目集规范族。
5. 构造 ACTION / GOTO 表。
6. 分析 token 流，输出 move / reduction / accept / error。
7. 每次 reduce 时同步构建 AST。

工程化改写：

- 函数名支持 `Ident` 和关键字 `main`。
- `funcDef` 与 `varDecl` 的 `int` 冲突通过统一类型入口缓解。
- dangling-else 使用 `matchedStmt / unmatchedStmt` 消歧。
- 表达式保留左递归，体现 SLR 对优先级文法的适配。

## 5. 语义分析

语义分析采用作用域栈和两阶段处理：

1. 全局预声明函数，允许先调用后定义。
2. 遍历 AST 检查声明、语句和表达式。

检查内容：

- 同一作用域重定义。
- 未定义变量。
- const 变量重新赋值。
- 函数实参数量检查。
- 函数实参与形参类型兼容检查。
- return 与函数返回类型匹配。
- `int -> float` 允许隐式转换，`float -> int` 报错。

输出 `*.semantic.log`，包含符号表和语义错误。

## 6. IR 后端

`src/ir.cpp` 是唯一 IR 后端边界，采用双路径设计：

1. `int/void` 必做子集使用给定 `compiler_ir` 中端库真实构造 IR。
2. `float` 扩展示例使用文本后端回退，因为给定中端库没有完整浮点常量和浮点二元指令封装。

`compiler_ir` 路径调用的核心接口包括：

- `Module` 管理全局变量和函数。
- `FunctionType / Function` 创建运行时声明和用户函数。
- `BasicBlock` 创建入口块、then/else/merge 块。
- `IRBuilder` 创建 `alloca / store / load / add / sub / mul / sdiv / srem / icmp / zext / br / ret / call`。
- `GlobalVariable / ConstantInt` 创建全局变量、全局常量和整型字面量。

支持能力：

- 运行时函数声明。
- 全局变量和常量。
- 函数定义。
- 函数参数。
- 局部变量 `alloca / store / load`。
- 整型表达式。
- 浮点表达式基础路径。
- 比较和逻辑表达式。
- 函数调用。
- if / else 基本块。
- int / float / void return。

工程支持两套构建方式：

- Makefile 直接编译 `external/compiler_ir/src/*.cpp` 并链接到 `cmmc`。
- CMake 在 `build/cmake` 下构建 `compiler_ir` 静态库，再链接到 `cmmc`。

整数主路径输出的 `label_*`、`declare`、`define`、`global/constant` 均来自中端库的打印器。

## 7. 命令和产物

```bash
./cmmc --lex input.sy
./cmmc --symtab input.sy
./cmmc --parse input.sy
./cmmc --ast input.sy
./cmmc --ast-dot input.sy
./cmmc --semantic input.sy
./cmmc --ir input.sy -o output.ll
./cmmc --dump-dfa input.sy
./cmmc --dump-first-follow input.sy
./cmmc --dump-lr0 input.sy
./cmmc --dump-slr input.sy
./cmmc --dump-all input.sy -o build/out
./cmmc --run-tests
```

构建命令：

```bash
make
make test
make demo
make ui
make cmake-build
make cmake-test
```

`--dump-all` 生成：

- `.tokens`
- `.symtab`
- `.dfa.csv`
- `.first`
- `.follow`
- `.lr0`
- `.slr.csv`
- `.parse`
- `.ast`
- `.ast.dot`
- `.semantic.log`
- `.ll`

## 8. 创新点

1. 自动化 SLR 构造器。
2. DFA、FIRST/FOLLOW、LR(0)、SLR、AST 全流程可视化输出。
3. 分层诊断系统。
4. 测试驱动的编译器前端。
5. `compiler_ir` 适配层与浮点 fallback 双后端。
6. 本地 Web UI，一键展示 tokens、符号表、规约过程、AST、语义日志、LLVM IR、DFA 和 SLR 表。

## 9. 测试体系

测试分为五类：

- 词法测试：大小写关键字、注释、浮点数、非法字符。
- 语法正确测试：声明、函数、参数、表达式、if/else、dangling else。
- 语法错误测试：缺括号、缺分号。
- 语义错误测试：未定义、const 赋值、参数数量错误。
- IR 测试：变量、const、表达式、函数调用、if/else、浮点 fallback。

一键测试：

```bash
make test
```

## 10. 展示 UI

```bash
make ui
```

UI 使用 Python 标准库提供本地服务，不引入额外依赖。浏览器端提交源码后，服务端临时写入 `.sy` 文件并调用 `./cmmc --dump-all`，然后把所有阶段产物打包成 JSON 返回给页面。页面用标签页展示各阶段结果，适合答辩演示和调试。
